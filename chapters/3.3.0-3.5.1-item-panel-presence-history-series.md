## Initial Mental Model

The 3.3 arc makes items richer by adding a Notion-style detail panel, hosting collaborative notes there, and introducing structured item properties such as status and assignee.

The 3.4 arc turns the collaboration shell into visible collaboration behavior: the board groups items by status, sharing UX is polished, and live presence is introduced on a realtime transport that is deliberately separate from Replicache structural sync.

The 3.5 arc starts history/revert work. 3.5.0 writes a mutation ledger from the Replicache push path. 3.5.1 reads that ledger for a read-only history/time-travel surface. 3.5.2 remains the planned revert/write-back phase.

## Candidate Study Questions

* How does `components/item/ItemDetailPanel.tsx` open from list and board item surfaces without remounting the dashboard data surface?
* How is the Yjs item note path hosted by the panel while keeping `ItemNoteDoc` separate from Replicache entities?
* How do `status`, `assigneeId`, and `boardOrderKey` flow through the existing `updateItem` mutator and server apply path?
* How does the board group by item status while preserving list/view/workspace filtering?
* What does the 3.4.0 presence spike prove, and what hardening is added in 3.4.3 before the 3.4.4 UI consumes it?
* Which code proves presence does not couple into Replicache push/pull?
* How are board rollups computed from committed synced data instead of in-flight drag previews?
* Where is the mutation ledger written, and why are no-op/rejected mutations excluded?
* What does the read-only history UI expose in 3.5.1?
* What must 3.5.2 add for true revert/write-back?
